# Contributing Guidelines

## Authority
- This file defines the rules for correctness in this repository.
- All agents and contributors must follow these rules.

## Workflow
- All changes must be done via feature branches and pull requests.
- Do not commit directly to main or protected branches.

## Code Standards
- Follow existing code style and architecture patterns.
- Do not introduce unnecessary refactors.
- Keep changes minimal and scoped to the task.

## Testing
- All changes must pass existing tests.
- New functionality should include tests when appropriate.
- Do not merge failing tests.

## Commits
- Use small, atomic commits.
- Do not mix unrelated changes in a single commit.

## Dependencies
- Do not add new dependencies unless necessary.
- Prefer existing libraries already used in the project.

## Security
- Never commit secrets or credentials.
- Do not weaken security mechanisms.

## Definition of Done
- Code builds successfully
- Tests pass
- Linting passes (if present)
- Changes are reviewed via pull request

## Scope Rules
- Only modify files relevant to the task.
- Do not perform unrelated improvements or refactors.
